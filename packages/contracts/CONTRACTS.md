# Proposed versioned contracts

## AgentDefinition (implemented v1alpha1)
`schema_version`, `id`, `version`, `display_name`, `description`, `capabilities[]`, `instructions` path, `skills[]` paths, `tools[]` built-in tool names (`current_time`, `read_agent_file`; unknown names fail `Definitions.resolve`), `mcp_servers[]` logical IDs, `runtime` (kind, model_profile, sandbox_profile), `budget` and `outputs[]`.

## ModelEndpointProfile (implemented v1alpha1)
One file per profile in `model-profiles/<id>.yaml` (gitignored: profiles are local, per-machine configuration), served at `GET /api/v1/model-profiles[/{id}]`. Fields: `schema_version`, `id`, `version`, `display_name`, `vendor`, `api_dialect` (`bedrock-converse`, `openai-compatible`, `anthropic`, `cli-adapter`), `endpoint` (`kind: amazon-bedrock`, `region`, `model_id`, `routing`: `in-region` | `geo` | `global`), `credential_ref` (a reference such as `aws:default-chain`, never a secret), `capabilities` (`input_modalities[]`, `streaming`), `timeout_seconds`, `max_retries`, Unknown fields are rejected so a stray `api_key` cannot be committed into a profile.

## TaskSubmission (preview implemented)
`agent_id`, `instruction`, optional `budget`. Optional `agent_revision` (40-hex commit sha, or a branch/tag name resolved to a sha at submit time; see Definition authoring). Future: `context_refs`, `artifact_targets`, `priority`, `idempotency_key`, `approval_policy`, `worker_class`.

## WorkerRegistration (credentials implemented in step 11; the rest planned)
Implemented: a worker is identified by its credential (see "Auth and audit"). Planned fields:
`worker_id`, `worker_version`, `architecture`, `capabilities[]`, `sandbox_profiles[]`, `capacity`, `heartbeat_interval_seconds`.

## ExecutionLease (implemented subset)
Implemented: `run_id`, `fencing_token`, `expires_at` (unix seconds) and `task` {`instruction`, `budget`, `reserved_tokens`, `pinned` (the PinnedDefinition incl. `definition_bytes` and base64 `files`)}. Never carries credentials. Planned fields:
`lease_id`, `fencing_token`, `run_id`, `expires_at`, `agent_git_revision`, `definition_digest`, `approved_policy_digest`, `runtime_profile`, `budget_reservation_id`, `scoped_credential_refs`.

## ExecutionEvent (planned)
`run_id`, `seq`, `event_type`, `timestamp`, `trace_id`, `payload` (typed by event type).

## ResultManifest (planned)
`run_id`, `status`, `agent_revision`, `model_endpoint_profile_revision`, `tool_versions`, `context_digests`, `usage`, `cost_provenance`, `artifacts` (URI, digest, MIME, size), `git_branch`, `git_commit`, `validation_results`, `failure_reason`.

## Compatibility policy
Schemas carry explicit API versions. Unknown fields should be rejected on security-critical command contracts; preserve backward compatibility for at least one minor release once public. Worker/controller capability negotiation must prevent unsupported policy downgrades.


## PinnedDefinition (implemented, internal)
An agent and its model profile pinned for a run (`Definitions.resolve`): `agent`, `profile`, `instructions` (decoded from the digested bytes), `git_rev`, `dirty`, `definition_digest` (sha256 over agent.yaml, instructions and skills), `profile_digest`. Unknown git state counts as dirty.

## Changes in this revision
`Budget.max_cost_usd` was replaced by `max_tokens` (total input + output tokens); there are no price schedules. `Runtime.kind` was removed: the dialect comes from the model profile.

## ExecutionEvent, ResultManifest, run ledger (implemented)
Ledger backends: `MAEF_DB` is a SQLite path (default `runs/maef.db`) or a `postgresql://user:pass@host/db` URL (needs the optional `postgres` extra, psycopg 3); the same `Ledger` interface and test suite run on both, and `Ledger.open(target)` picks the adapter. Postgres starts at the latest schema (`schema_version` table, BIGINT tokens, JSONB payloads); admission locks the budget account row (`FOR UPDATE`) and `claim` leases the oldest queued run with `FOR UPDATE SKIP LOCKED`, so many API and worker processes can share one database. `run_events` and `audit_log` reject UPDATE/DELETE on both (SQLite triggers, a Postgres trigger function). `run_events` is append-only (triggers reject UPDATE/DELETE) with gapless `seq` per run. Usage is integer tokens as reported by the provider. Admission reserves `min(max_tokens, worst-case tokens)` in one write transaction (`BEGIN IMMEDIATE` on SQLite, row locks on Postgres) and fails closed on dirty or unknown git state (dirty allowed only with an explicit flag, recorded in the `task.created` event). `settle` charges the actual tokens and returns the remainder. Read-only `GET /api/v1/runs` and `GET /api/v1/runs/{id}`.

## Execution (implemented)
`POST /api/v1/runs` returns 202 `{run_id}` when `MAEF_EXECUTION_ENABLED=1` (otherwise 501) after admitting and queuing the run; a separate worker process (`python -m maef_api.worker`) executes it. A turn loop (see below) over the profile's `max_output_tokens`, timeout and retries. Events: `run.started`, per turn `model.request` (`turn`, `prompt_bytes`, `tools`), `model.response` (`turn`, `stop_reason`, `tool_calls`, `latency_ms`, and `provider`, `response_id`, `model` when the provider reports them), `usage.recorded` (`turn`, `input_tokens`, `output_tokens`, `total_tokens`, `cache_read_tokens`, `cache_write_tokens`, `reasoning_tokens`, and `cost_usd` when reported; `reasoning_tokens` is the part of `output_tokens` spent on reasoning and `cost_usd` is provider-reported and information only; `input_tokens` counts all prompt tokens including cached reads and writes, and the two cache fields are the parts of it served from or written to the prompt cache; events recorded before these fields existed are read as 0), `tool.call` (`turn`, `name`, `argument_bytes`), `tool.result` (`turn`, `name`, `result_bytes`, `is_error`, `duration_ms`), then `run.output`, `run.manifest`, (with `MAEF_RECORD_TRANSCRIPT=1` on the worker, `transcript.recorded` {`records`, `bytes`, `truncated`} just before `run.manifest`, or `transcript.failed` {`code`}), then the terminal `task.*` event. 

**Run lifecycle:** `admitted` (queued, claimable) -> `leased` -> `running` -> `succeeded` | `failed` | `cancelled`. Queued runs survive an API restart.

**Worker protocol (`/api/v1/worker/`, `Authorization: Bearer $MAEF_WORKER_CREDENTIAL`, a per-worker credential; 401 if missing, wrong or revoked):** `POST claim` {} -> 200 Lease | 204 (a `worker_id` in the body is ignored: the lease binds to the credential's worker); `POST runs/{id}/heartbeat` {fencing_token}; `POST runs/{id}/events` {fencing_token, wseq, type, payload, status} -> {appended}; `POST runs/{id}/finish` {fencing_token, tokens_used, status, terminal_reason}. Conflicts are 409 `{detail: {code: "fencing" | "sequence_gap"}}`. `wseq` is the worker's own gapless counter from 1: a repeat is ignored (`appended: false`), a gap is refused. Workers may only set status `running` and may not write `task.*` or `lease.*` events. The ledger adds `lease.granted` and `lease.expired`. A lease that is not renewed within `MAEF_LEASE_SECONDS` (default 60) is swept (startup and every 10 s): the run fails as `worker_lost` and its whole reservation is charged. Before running, the worker recomputes the definition digest from the bytes in the lease; a mismatch finishes the run `failed`/`definition_mismatch` with 0 tokens and no model call. In-process execution (the ADR-0002 interim exception) is gone.

## Endpoint kinds (implemented)
`endpoint.kind`: `amazon-bedrock`, `openai-compatible` (OpenAI or any local chat/completions server; `base_url`, `token_param`) and `anthropic` (Messages API). `api_dialect` must match the kind. `base_url` must be https, or http on loopback only, with no embedded credentials. `credential_ref` is `aws:default-chain`, `none:local` or `env:NAME`; the key is read from the environment at call time and never stored or logged. HTTP errors record status and class only, never bodies. A missing `usage` block fails the call, since the budget cannot be metered. Other endpoint kinds plug in by adding a kind and an adapter.

## Credentials and egress (implemented)
`Credentials.resolve(credential_ref)` returns an opaque `Secret` (`reveal()` is the only way to read it; repr/str/format print `Secret(***)`) or `None` for `none:local` and `aws:default-chain` (Bedrock uses the boto3 default chain itself). A missing or empty `env:NAME` raises `CredentialError("missing_credential:NAME")`, naming the variable only. Every HTTP model call passes through `EgressPolicy.check` before each attempt: all resolved addresses must be allowed; unspecified, multicast, reserved and link-local (including 169.254.169.254, fe80::/10, fd00:ec2::254) are always denied, IPv4-mapped/compatible IPv6 is evaluated as the embedded v4, loopback is allowed only when the profile host is loopback, and private ranges (RFC1918, 100.64/10, fc00::/7) only with `endpoint.allow_private_network: true`. Plain `http` base URLs require a loopback host or that flag. Redirects are not followed. Known gap (model calls only): DNS is resolved again by the HTTP client at connect time (rebinding TOCTOU). The address rules live in `egress_proxy.classify_address`, shared with the MCP egress proxy, which does not have this gap.


## Conversation, tools and budget guard (implemented)
Neutral types in `adapters/base.py`: `ToolSpec(name, description, input_schema)`, `ToolCall(id, name, arguments, parse_error)`, `Message(role: user|assistant|tool, text, tool_calls, tool_call_id, is_error)`, `ModelResponse(text, tool_calls, stop_reason, input_tokens, output_tokens)`. `stop_reason` is normalised to `end_turn` | `tool_use` | `max_tokens` | `other:<raw>`. `ModelAdapter.converse(system, messages, tools, max_output_tokens, timeout_seconds)` is one non-streaming call; each adapter (openai-compatible, anthropic, bedrock-converse) translates to and from its wire format. The openai-compatible adapter tolerates local servers (Ollama, LM Studio): `arguments` as a string or object, missing tool call ids (`call_<index>`), `finish_reason: stop` with tool calls (treated as `tool_use`), null content, and omits `tools` when there are none. Unparseable arguments keep the call with `{}` and `parse_error`, and the harness returns an error tool result without invoking.

`BudgetGuard(budget, reserved_tokens, max_output_tokens)` (`guard.py`): `check(prompt_bytes)` returns `turns_exhausted`, `duration_exhausted`, `tokens_exhausted` (`tokens_used + prompt_bytes + max_output_tokens > reserved_tokens`) or `None`; `record(input, output)` after each call. A stop reason ends the run `failed` with that terminal reason. Prompt bytes include the system prompt, message text, tool call arguments and tool definitions, and admission counts the tool definitions too.

`ToolSet` (`tools.py`): `specs()` and `invoke(name, arguments) -> ToolResult(content, is_error)`, which never raises. `BuiltinTools` provides read-only `current_time` and `read_agent_file` (`{"path"}`: only the agent's instructions file and listed skills; no symlinks or traversal). Results are capped at 32 KiB with a truncation marker. Events never contain argument or result contents. Terminal reasons: `completed`, `output_truncated`, `unsupported_stop_reason:<x>`, `malformed_response`, `model_error:<Class>` and the guard reasons above.


## Sandbox (implemented)
`SandboxProfile` (`sandbox-profiles/<id>.yaml`, extra fields forbidden): `schema_version`, `id`, `image`, `cpus`, `memory_mb`, `pids_limit`, `workspace_mb` (tmpfs size), `network: none` (only option), `require_rootless` (default true), `user` (default `65534:65534`). `image` must be `...@sha256:<64 hex>`; a tag-only image is refused at provisioning unless the worker env has `MAEF_ALLOW_UNPINNED_IMAGES=1`. `Definitions.resolve` pins it like the model profile (`PinnedDefinition.sandbox`, `sandbox_digest`); it is required, and `ResolveError` otherwise, only when the agent lists a tool in `SANDBOXED_TOOLS` (`run_command`).

Seam (`sandbox.py`): `Sandbox.provision(profile, run_id) -> Session`, `Sandbox.info() -> {runtime, version, rootless}`. `Session`: `exec(argv, *, stdin, timeout) -> ExecResult(exit_code, stdout, stderr, timed_out)` (each stream capped at 64 KiB), `put(path, bytes)`, `get(path) -> bytes`, `teardown()` (idempotent). Paths must be under `/workspace`; `..` is rejected. Adapters: `OciCliSandbox` (podman or docker CLI; `detect_sandbox()`, `MAEF_OCI_RUNTIME`) and `FakeSandbox`. `SandboxUnavailable` (no runtime, not rootless when required, unpinned image, provision failure) is fail-closed.

Tool `run_command` `{argv: [str], stdin?: str}` returns JSON `{exit_code, stdout, stderr, timed_out}` (streams capped at 12 KiB each in the result); per-exec timeout is `min(30 s, remaining run duration)`. Events: `sandbox.provisioned` `{runtime, version, rootless, profile, unpinned_image_allowed}` before `run.started`, `sandbox.torn_down` `{profile}` before the terminal event. A run that needs a sandbox when none is usable ends `failed` / `sandbox_unavailable` with 0 tokens and no model call.


## MCP server manifests (implemented, stdio only)
One file per server in `mcp-servers/<id>.yaml` (`McpServerRegistry`; same id and symlink rules as the other registries), `extra=forbid`: `schema_version`, `id`, `version`, `transport: stdio`, `image` (digest-pinned, or tag-only with `MAEF_ALLOW_UNPINNED_IMAGES=1` on the worker; checked at provisioning), `command` (argv run inside the image), `env` (non-secret values), `secrets` (`ENV_NAME: env:CREDENTIAL_VAR`, resolved on the worker host by `Credentials`, never stored or logged; passed to the container CLI through its process environment, not argv), `network: none|allowlist|open` (with `allowed_hosts`/`allowed_ports` for allowlist), `permission: read-only|side-effects` (declared, not yet enforced), `max_tools` (default 32). Environment names that could alter the host CLI (`PATH`, `HOME`, `LD_*`, `DOCKER_*`, `XDG_*`, ...) are rejected.

Agents reference servers as `mcp_servers: ["<id>@<version>"]`; `Definitions.resolve` requires the manifest version to match exactly. `PinnedDefinition.mcp_servers` holds the manifests and `mcp_bytes` their exact bytes; `compute_definition_digest(agent_yaml, files, mcp_bytes)` digests each as `mcp-servers/<id>.yaml` after `files`, sorted by id (no MCP servers: digest unchanged). The worker re-parses `mcp_bytes` and rejects `definition_mismatch` if they differ from the pinned manifests or the agent's references.

**`AgentDefinition.permissions.network_open`** (default `false`): a manifest with `network: allowlist` or `open` is only admitted when the agent sets it (`ResolveError` otherwise; the worker re-checks and rejects `network_not_permitted`). Each MCP server gets its own container (its image, the agent's sandbox-profile resource limits or conservative defaults, same hardening); `network: open` uses the runtime's default network.

**Network modes.** `none`: `--network=none`. `allowlist` (preferred for any network access): enforced egress proxy, below. `open`: the runtime's default network, **unfiltered** (reaches the LAN and cloud metadata); discouraged, kept for servers that cannot honour `HTTP(S)_PROXY`.

**Allowlist semantics** (`network: allowlist` requires non-empty `allowed_hosts`; `allowed_hosts`/`allowed_ports` are rejected for other modes). `allowed_hosts`: exact hostnames, `*.suffix` (any subdomain of suffix, not suffix itself), or `*` (any host, still subject to the public-address rule). Matching is case-insensitive on the IDNA (punycode) form, trailing dot ignored. `allowed_ports` (default `[443, 80]`) are destination ports; plain HTTP is forwarded only to port 80. Regardless of the host list the proxy resolves the name itself and denies the request if ANY resolved address is loopback, private (RFC1918, 100.64/10, fc00::/7), link-local/metadata (169.254.169.254, fd00:ec2::254), unspecified, multicast or reserved (IPv4-mapped IPv6 evaluated as v4, IP literals and numeric forms included), then connects to the vetted IP (no second resolution: DNS rebinding cannot swap the target). An allowlist agent needs `permissions.network_open` (same permission as `open`).

**Per-run topology** (`OciCliSandbox`, podman and docker): `network create --internal maef-egress-<run>-<rand>` (label `maef.run`); proxy container `maef-proxy-<run>-<rand>` (label `maef.run`; image `sandbox.EGRESS_PROXY_IMAGE`, `python:3.12-alpine` pinned by manifest-list digest; read-only, cap-drop ALL, no-new-privileges, uid 65534, pids/memory/cpu limits, source passed with `python -c`, config as JSON in `MAEF_EGRESS_CONFIG`) started on the default network (`podman` / `bridge`) and then connected to the internal network (podman: the internal network has `--disable-dns` so the proxy keeps the host resolvers); it only serves clients from the internal subnet. The MCP container joins ONLY the internal network and gets `HTTP_PROXY`/`HTTPS_PROXY` (both cases) = `http://<proxy internal IP>:3128` and an empty `NO_PROXY`; traffic that ignores the proxy has no route. Proxy: `CONNECT host:port` and absolute-form `GET|HEAD http://...` (no request bodies); 403 + short reason code on deny, 502 on connect failure, 503 when more than 32 connections are open; per-connection idle timeout 60 s; 256 MiB total bytes per run (then new requests are denied). One JSON line per decision on stdout (host, port, decision allow|deny|error, reason, bytes), never paths, URLs or bodies. Teardown removes the session container, the proxy and the network (idempotent); `cleanup_orphans` also removes labelled networks. `Session.egress_summary()` returns {decisions, hosts, bytes} parsed from the log before teardown.

**Egress events:** `egress.proxy_started` {server, allowed_hosts (count), any_public_host, ports} after `mcp.started`; `egress.summary` {server, decisions: {allow|deny|error: n}, hosts: {host: {decision: n}} (capped at 200 hosts), bytes} after `mcp.stopped`. Residual risks: DNS queries for allowed names go to the host's resolvers (a low-bandwidth covert channel), and `*` lets a compromised server exfiltrate to any public host (use a real host list for servers that handle sensitive data).

**Runtime (`mcp.py`):** newline-delimited JSON-RPC 2.0 over the spawned process (`Session.spawn(argv, env=) -> Process{write, readline(timeout), close}`): `initialize` (protocol `2025-06-18`), `notifications/initialized`, paginated `tools/list` (truncated to `max_tools`), `tools/call`. Tools are exposed as `mcp__<server_id>__<tool>`; descriptions are untrusted (control characters stripped, 1 KiB cap), a tool whose `inputSchema` is not an object is skipped, lines over 1 MiB and malformed JSON are errors, `invoke` never raises. `CompositeToolSet` merges tool sets and rejects duplicate names.

**Events:** `sandbox.provisioned` gains `network` and `network_open` (one per container; MCP containers also carry `server`); `mcp.started` {server, version, tool_count, network}; `mcp.tools_truncated` {server, listed, max_tools}; `mcp.stopped` {server}; `tool.call`/`tool.result` carry `server` for MCP tools. Startup failures finish the run `failed` before any model call: `credential_missing:<ENV>`, `mcp_unavailable:<server>` (the `run.rejected` event has a `code`).

**Admission estimate:** MCP tool specs are unknown at admission, so `Runs.submit` adds a fixed 8 KiB of prompt bytes per server (`mcp.ADMISSION_ALLOWANCE_BYTES`). If the real specs exceed it, the budget guard stops the run (`tokens_exhausted`) rather than overspending.

## Artifacts (implemented)
`ArtifactRef` `{digest: "sha256:<64 hex>", size, mime, name}`. `name` is a sanitised basename (no separators or control characters, at most 128 characters); `mime` is one of `text/markdown`, `text/plain`, `application/json`, `text/csv`, `image/png`, `image/jpeg`, `application/pdf`, `application/octet-stream`, anything else becomes `application/octet-stream`. Bytes live in an `ArtifactStore` (`put`, `read` verifying the sha256, `exists`): `LocalArtifactStore` at `<root>/sha256/<aa>/<rest>` (root `MAEF_ARTIFACTS_DIR`, default `artifacts/`, gitignored; atomic temp-file + rename, deduplicated by digest) and `InMemoryArtifactStore`. Limits: 50 MiB per artifact, 32 artifacts and 200 MiB per run.

**What becomes an artifact:** the final model text is stored as `output.md` (`text/markdown`); the `run.output` event now carries only the ref fields `{digest, size, mime, name}` (or `{error, bytes}` if it was refused), not the text. If the run had a built-in sandbox session, regular files directly under `/workspace/out/` (no recursion, symlinks skipped, each at most 8 MiB because of the sandbox read cap) are collected after the model loop with a mime guessed from the extension; problems are recorded as `outputs.collected` `{count, skipped:[{name, reason}]}` or `outputs.collection_failed` `{code}` and never fail the run. `ResultManifest.artifacts: list[ArtifactRef]` lists them all. Every stored artifact emits `artifact.stored` `{name, digest, size, mime}` (ledger-written; the `artifact.` event prefix is reserved) and a row in `run_artifacts(run_id, seq, digest, size, mime, name)` (ledger migration 4).

**Upload (worker):** `POST /api/v1/worker/runs/{id}/artifacts?name=..&mime=..`, raw body, headers `Authorization: Bearer $MAEF_WORKER_CREDENTIAL`, `X-Fencing-Token`, `X-Content-Digest: sha256:<hex>` -> 200 `ArtifactRef`. The server recomputes the digest: mismatch 400 `{code: "digest_mismatch"}`; over a limit 413 `{code: "too_large" | "run_limit"}`; stale lease 409 `{code: "fencing"}`. Repeating the same (digest, name) for a run is idempotent. `WorkerChannel.upload(lease, *, name, mime, data) -> ArtifactRef`.

**Read:** `GET /api/v1/runs/{id}/artifacts` -> `ArtifactRef[]` (404 unknown run). `GET /api/v1/artifacts/{digest}` -> bytes, only for digests recorded for some run (404 otherwise); verified on read; headers `Content-Type` (stored mime), `Content-Disposition: attachment; filename="<name>"`, `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox`.

**Artifact backends (implemented, step 12b):** the `ArtifactStore` protocol (`put(data, name=, mime=)`, `read`, `exists`) has two adapters selected by `default_artifact_store()`. Local (default): `MAEF_ARTIFACTS_DIR` (else `<root>/artifacts`), layout `sha256/<aa>/<rest>`. S3-compatible (`S3ArtifactStore`, optional extra `.[s3]`): `MAEF_ARTIFACTS_URL=s3://bucket/prefix`, keys `<prefix>/sha256/<aa>/<rest>`. Objects are write-once: `put` HEADs first and skips the upload when an object of the same size exists; a size mismatch raises `ArtifactCorrupt` and never overwrites. Uploads carry `ContentType` (sanitised mime), metadata `maef-name`, `ServerSideEncryption=AES256` (unless disabled) and a SHA-256 additional checksum (dropped automatically for servers that reject it). `read` re-verifies the sha256 (`ArtifactCorrupt` on mismatch, `ArtifactNotFound` on 404); other S3 failures raise `ArtifactError("store_unavailable")` with no server detail. Environment: `MAEF_S3_ENDPOINT_URL` (S3-compatible servers; checked by the egress policy: loopback allowed only for loopback hosts, private ranges only with `MAEF_S3_ALLOW_PRIVATE=1`, link-local/metadata never), `MAEF_S3_REGION`, `MAEF_S3_ADDRESSING_STYLE` (`auto`|`path`|`virtual`; most S3-compatible servers need `path`), `MAEF_S3_SSE` (`0` disables SSE for servers that reject it), `MAEF_S3_ACCESS_KEY_REF` / `MAEF_S3_SECRET_KEY_REF` (`env:NAME` references; unset means the boto3 default credential chain).

## Live events and cancel (implemented)
**SSE:** `GET /api/v1/runs/{id}/events` -> `text/event-stream` (404 unknown run; headers `Cache-Control: no-store`, `X-Accel-Buffering: no`). Resume from `?after=<seq>` or the `Last-Event-ID` header (the header wins; default 0). Each event is `id: <seq>\nevent: <type>\ndata: {"seq","type","ts","payload"}\n\n`, in seq order, exactly the `run_events` rows (never prompts, tool arguments/results or secrets). The server polls the ledger every 0.5 s (`main.sse.poll_seconds`), sends `: keepalive` after 15 s of silence (`main.sse.keepalive_seconds`), and closes right after delivering the terminal `task.succeeded|failed|cancelled` event, immediately if the run is already terminal and nothing newer than the cursor exists, when the client disconnects, or after 1 hour (`main.sse.max_seconds`; clients reconnect with `Last-Event-ID`). Ledger: `events_after(run_id, after_seq, limit=500)`, `status(run_id)`, `is_terminal(run_id)`; `Runs.events_after` / `Runs.status` pass through.

**Cancel:** `POST /api/v1/runs/{id}/cancel` -> 202 `{"outcome": "cancelled" | "requested"}`; 404 unknown run; 409 `{code: "already_terminal"}`. A queued (`admitted`) run is settled at once: `cancel.requested` then `task.cancelled` (`terminal_reason: cancelled_by_user`, 0 tokens, reservation released) -> `"cancelled"`. A `leased`/`running` run gets `runs.cancel_requested = 1` (ledger migration 5) and one `cancel.requested` event -> `"requested"` (repeat calls return `"requested"` without another event; `RunRecord.cancel_requested` exposes the flag). `cancel.` is a reserved event prefix.

**Worker side:** `Ledger.heartbeat` and `Ledger.report` return the flag; `WorkerChannel.heartbeat/report` return `cancel_requested: bool` (note: `report` no longer reports duplicates). HTTP: the worker `heartbeat` response is `{"ok": true, "cancel_requested": bool}` and `events` is `{"cancel_requested": bool}`. The worker keeps a `threading.Event` set by its heartbeat thread or any report response (so latency is at most one heartbeat interval, 15 s). `BudgetGuard(..., cancelled=callable)`: `check()` returns `"cancelled"` first; the harness also checks before each tool call and skips the remaining calls of a turn. The run ends `cancelled` / `cancelled_by_user`, charging the usage so far, with the usual sandbox and MCP teardown and the manifest written. `Session.exec(..., cancel=Event)` kills a running exec within about 0.25 s (best effort, like a timeout) and returns `ExecResult.cancelled`; `run_command` then returns `{..., "cancelled": true}` as an error result. `Ledger.finish` accepts status `cancelled`. A worker that never reports leaves the run to the lease sweep (`worker_lost`).

## Host gateway (implemented)
`MaefClient(transport)` (`maef_api/client.py`) is the single client over the public run API: `list_agents`, `preview`, `submit`, `get_run`, `list_runs`, `cancel`, `artifacts`, `download`, `events(id, after=0)` (SSE parsing, `Last-Event-ID` resume), `wait(id, timeout_seconds)`, `result_text(id)` (the `output.md` artifact, UTF-8 with replacement). Errors are `MaefClientError(status, code, message)` built only from the API's JSON `detail`. Transport seam: `request(method, path, *, json, headers) -> (status, headers, body)` and `stream(path, headers) -> lines`; adapters `HttpTransport(base_url, timeout, allow_private=False)` (urllib, no redirects, egress check with loopback allowed only for loopback URLs; `MAEF_API_URL`, default `http://127.0.0.1:8000`) and `AsgiTransport(app)` (tests).

`maef` CLI (`maef_api/cli.py`): `agents`, `preview`, `run [--wait --timeout --json]`, `status`, `events [--follow]`, `cancel`, `artifacts`, `get DIGEST -o PATH [--force]`, `result`, `mcp`. Exit codes: 0 ok, 1 run failed/cancelled, 2 usage/API error, 3 timeout.

`maef mcp` (`maef_api/gateway.py`, `Gateway(client, stdin, stdout).serve()`): newline-delimited JSON-RPC 2.0 over stdio, sequential, logs to stderr. Methods: `initialize` (echoes the client protocol version if one of 2025-06-18, 2025-03-26, 2024-11-05, else 2025-06-18), `notifications/*`, `ping`, `tools/list`, `tools/call`; unknown method -32601, bad JSON -32700, bad envelope -32600. Tools: `list_agents`; `delegate {agent_id, instruction, max_tokens?, max_turns?, max_duration_seconds?, wait_seconds? (0-600, default 0)}`; `run_status {run_id}`; `run_result {run_id}`; `cancel_run {run_id}`. Results are `content: [{type: "text"}]`; API errors are `isError: true` with the detail message. Agent result text is untrusted: wrapped as `<maef-result run_id="..." status="...">...</maef-result>` and capped at 100 KiB with a truncation marker. Only agent id, display name and description are listed; tools, MCP servers, credentials and instructions are never exposed.

## Request budgets
`RunRequest.budget` is a `BudgetOverride`: each field is optional and may only tighten the agent ceiling; omitted fields keep the ceiling.

## Decision models (implemented, step 9)
Details and verified wire formats: `docs/DECISION_MODELS.md`. Endpoint kinds `decisions-api` (`base_url` default `https://decisions-api.dev`, `model_id`; dialect `decisions-api`) and `cloudflare-workers-ai` (`account_id`, `model_id` `@cf/...`, `base_url` default `https://api.cloudflare.com/client/v4`; dialect `workers-ai-decision`) follow the same https/egress/`credential_ref` rules as other HTTP kinds. Agents cannot use these dialects (501).

`POST /api/v1/decisions` {`profile_id`, `state` (string|object|array, <= 64 KiB), `questions` ({name: {`type`: choice|score|noul, `instructions`, `criteria`}}, 1-8, name `^[a-z][a-z0-9_]{0,40}$`; choice criteria `{option: description}` 2-20, score criteria ordered list 2-10, noul optional `{true,false}`), `max_tokens`?} -> 202 {`run_id`, `status`}; 404 unknown profile, 409 `not_a_decision_profile` or admission codes, 501 execution disabled. The run (`RunRecord.kind: "decision"`, `agent_id: "decision:<profile>"`, digests are the pinned profile bytes' sha256) reserves `min(max_tokens or 50000, request bytes + 1024)` tokens in the same account. `TaskPayload.kind` is `agent` (`instruction`, `pinned`) or `decision` (`decision`: `request`, `profile`, base64 `profile_bytes`, `profile_digest`). Events: `run.started`, `decision.request` {profile, questions (names), state_bytes}, `usage.recorded`, `artifact.stored`, `run.output`, `run.manifest`, `task.*`. Result: artifact `answers.json` (`application/json`) `{"answers": {name: {type, value, confidence?, probabilities?}}}` where `value` is the chosen option (choice), the fractional 0-based level (score) or P(yes) (noul). Usage is provider-reported; unreported usage is charged as the request bytes. Client: `MaefClient.decide(profile_id, state, questions, max_tokens)` and `answers(run_id)`; CLI `maef decide`; gateway tool `decide`.

## Definition authoring (BACKEND_PLAN step 10)
**Schemas:** `schemas/{agent-definition,model-endpoint-profile,sandbox-profile,mcp-server-manifest}.schema.json` are exported from the pydantic models (`model_json_schema()`, sorted keys, 2-space indent, trailing newline). `maef schema export [--dir DIR]` writes them; `maef schema export --check` writes nothing and exits 1 when a committed file is missing or differs (for CI). `GET /api/v1/schemas/{name}` serves the same schema (404 unknown name).

**Lint:** `lint.lint_repo(root, only_agent=None) -> list[Finding]` (`path`, `message`, `severity` error|warning) is pure file reading. It checks every `agents/*/agent.yaml` (schema; id equals the directory; instructions and skills exist as regular files inside the agent directory, no symlinks; tools are built-ins; `mcp_servers` are `<id>@<version>` and resolve to `mcp-servers/<id>.yaml` at exactly that version; an MCP server with `network: open` needs `permissions.network_open`, and the reverse is a warning; the sandbox profile exists, an error when `run_command` is used; the model profile exists in `model-profiles/` is a warning, only when that directory is present), and `sandbox-profiles/`, `mcp-servers/`, `model-profiles/` (schema, id equals file name). `maef lint [PATH...]` prints `path: message` (`path: warning: message`) and exits 1 on any error (default PATH is this repository; a PATH limits the output to files under it).

**Pinned revision:** `RunRequest.agent_revision`. `Definitions.resolve(agent_id, revision=None)` with a revision reads agent.yaml, instructions, skills, the sandbox profile and MCP manifests from that commit's object store (`git ls-tree` + `git cat-file`; paths must be plain relative paths, only regular files, no symlinks). `git_rev` is the resolved sha and `dirty` is false; the digest algorithm is unchanged, so worker verification is the same. Model profiles are local and still read from disk. An unknown or malformed revision, or a definition missing at that commit, is a `ResolveError` (`POST /api/v1/runs` -> 409). Revision expressions such as `HEAD~1` are refused; only a sha, a branch or tag name, or `HEAD`.

**Drafts (`drafts.Drafts(repo_root)`; routes need `MAEF_AUTHORING_ENABLED=1`, otherwise 501; all draft routes need the `authoring` scope):**
- `POST /api/v1/drafts` {`agent_id`} or {`new_agent_id`} -> 201 Draft {`id` (12 hex), `agent_id`, `branch` (`maef/draft/<agent>/<id>`), `base` (HEAD sha), `created_at`, `new_agent`, `published`}. A git worktree is created under `runs/drafts/<id>` (gitignored). `GET /api/v1/drafts` lists drafts.
- `PUT /api/v1/drafts/{id}/files/{path}` (text/plain UTF-8 body, <= 256 KiB) writes `path`, a repo-relative file under `agents/<agent>/`. Rejected: `..`, absolute paths, other agents or directories, dot-files, symlinks, binary content (400 `invalid_path`/`invalid_content`, 413 `too_large`).
- `GET /api/v1/drafts/{id}/review` -> Review {`base`, `diff` (unified diff of the agent directory vs base), `files`, `permissions`, `findings`, `publishable`}. `permissions`: `new_agent`, `tools_added/removed`, `mcp_servers_added/removed`, `network_open` {field, before, after} when `permissions.network_open` changed, `budget_increases` (each budget field that rose, or all for a new agent), `runtime_changes` (model/sandbox profile), `mcp_new_secrets` ({server ref: secret env names not present at base}), `mcp_network_open_added` (server refs whose manifest has open network and did not at base).
- `POST /api/v1/drafts/{id}/publish` {`message`} -> {`draft_id`, `revision`}: refused (409 `lint_failed`, `no_changes`) when lint has errors for that agent or nothing changed; otherwise commits on the draft branch as `MAEF Authoring <maef@localhost>` (`MAEF_AUTHORING_NAME`, `MAEF_AUTHORING_EMAIL`), hooks and signing disabled. It never merges or pushes: a human merges the branch after review (ADR-0003). Run the commit at once with `agent_revision=<revision>` (a pinned revision is never dirty).
- `DELETE /api/v1/drafts/{id}` removes the worktree and record, and the branch unless the draft was published (the published commit stays reachable).
Client: `MaefClient.draft_create/draft_list/draft_write/draft_review/draft_publish/draft_discard`, `submit(..., agent_revision=)`, `schema(name)`; `Transport.request` takes an optional raw `data` body. CLI: `maef draft new [AGENT | --new-agent ID]`, `write ID PATH [FILE|-]`, `review ID`, `publish ID -m MSG`, `discard ID`, `list`; `maef run AGENT TASK --revision SHA`.

## Auth and audit (implemented, BACKEND_PLAN step 11)
**Tokens:** API tokens are `maef_<32 random bytes, urlsafe>`, worker credentials `maefw_<...>`. Each is shown once at creation; only its sha256 is stored (`api_tokens`, `worker_credentials`). Verification looks up the hash, then `hmac.compare_digest`. Create and revoke with the local bootstrap CLI, which opens the ledger (`MAEF_DB`) directly and is the root of trust: `maef admin token create --name N --scopes a,b | list | revoke ID`, `maef admin worker create --id ID | list | revoke ID` (revoking a worker id revokes all its credentials). Clients send `Authorization: Bearer $MAEF_API_TOKEN` (CLI, gateway, TUI); workers use `MAEF_WORKER_CREDENTIAL`. `MAEF_WORKER_TOKEN` no longer exists.

**Scopes** (`admin` implies all): `read`, `runs:write`, `decisions:write`, `authoring`, `admin`. 401 (with `WWW-Authenticate: Bearer`) for a missing, invalid or revoked token; 403 for a valid token without the scope.

| Route | Scope |
|---|---|
| `GET /health` | none (reports `auth_required`) |
| `GET /api/v1/metrics`, `GET /api/v1/agents[/{id}[/files]]`, `model-profiles[/{id}]`, `schemas/{name}`, `runs`, `runs/{id}`, `runs/{id}/events`, `runs/{id}/artifacts`, `artifacts/{digest}`; `POST runs/preview` | `read` |
| `POST /api/v1/runs`, `POST runs/{id}/cancel` | `runs:write` (audited) |
| `POST /api/v1/decisions` | `decisions:write` (audited) |
| `/api/v1/drafts` (list, review: GET; create, file write, publish, discard: audited) | `authoring` |
| `GET /api/v1/audit?after=&limit=` | `admin` |
| `/api/v1/worker/*` | worker credential (not an API token) |

**Dev escape hatch:** `MAEF_AUTH_DISABLED=1` skips API-token checks only when `request.client.host` is loopback (principal `dev-unauthenticated`); a non-loopback client without a valid token gets 403. A warning is logged at startup. It never applies to worker routes.

**Worker identity:** `claim` binds the lease to the authenticated worker; heartbeat, events, finish and artifact upload from a different worker are refused as 409 `fencing`.

**Audit:** `audit_log(seq, ts, principal, action, target, outcome, client)`, append-only (UPDATE/DELETE triggers). `principal` is `token:<id>`, `worker:<id>`, `dev-unauthenticated`, `anonymous` or `local-cli` (bootstrap CLI). `action` is `METHOD /route/{template}` (CLI: `token.create|revoke`, `worker.create|revoke`); `target` the concrete path or `token:<id>`/`worker:<id>`; `outcome` `allowed`, `denied:401`, `denied:403` or `ok`/`not_found` (CLI). Recorded: every run submit/cancel, decision, draft create/write/publish/discard, worker lease grant and finish, every 401/403, and the CLI admin actions. Not recorded: bodies, tokens, idle claims, heartbeats, worker events (those are run events). `GET /api/v1/audit` returns rows after `seq`, oldest first (limit 1-1000). A mutating request whose audit row cannot be written is refused (500).

**Auth refinements:** `MAEF_AUTH_DISABLED=1` applies only to loopback requests that send no `Authorization` header at all (a presented token must be valid) and never grants `admin`. Audit rows written by the auth dependency have outcome `authorized` (checked before the handler runs); run-creating routes add a `run.created` row whose target is the new run id.

## Observability and evals (implemented, BACKEND_PLAN step 14)
**Span mapping (`otel.run_to_spans`).** Trace id = sha256(`maef:trace:<run_id>`)[:32]; span id = sha256(`maef:span:<run_id>:<key>`)[:16] with key `root` or the starting event's `seq`. Resource `service.name=maef`, scope `maef.ledger`; semconv recorded as `maef.semconv`.

| Span | Name | Start / end events | Attributes |
|---|---|---|---|
| root | `maef.run` | `task.created` / terminal `task.*` (last event if still live) | `gen_ai.operation.name=invoke_agent`, `gen_ai.agent.name`, `gen_ai.request.model`, `gen_ai.usage.input_tokens`, `gen_ai.usage.output_tokens`, `maef.run_id`, `maef.run.kind`, `maef.run.status`, `maef.agent_revision`, `maef.dirty`, `maef.terminal_reason`, `maef.tokens_used`, `maef.tokens_reserved`. Status: succeeded OK, failed ERROR (message = terminal reason), cancelled UNSET |
| model turn (CLIENT) | `chat <profile>` | `model.request` / last of `model.response`, `usage.recorded` for the turn | `gen_ai.operation.name=chat`, `gen_ai.request.model` (profile id), `gen_ai.request.max_tokens`, `gen_ai.response.finish_reasons`, `gen_ai.usage.*` (including `gen_ai.usage.cache_read.input_tokens` and `gen_ai.usage.cache_creation.input_tokens`; the `maef.run` span carries their sums), `maef.turn`, `maef.stop_reason`, `maef.prompt_bytes`, `maef.tools_offered`, `maef.tool_calls`, plus `maef.usage.reasoning_tokens`, `maef.usage.cost_usd`, `gen_ai.response.id`, `gen_ai.response.model`, `maef.provider`, `maef.latency_ms` when known |

| sandbox | `maef.sandbox` | `sandbox.provisioned` / `sandbox.torn_down` | `maef.sandbox.profile`, `.network`, `.network_open` |
| MCP server | `maef.mcp <server>` | server's `sandbox.provisioned` / `mcp.stopped` | `maef.mcp.server`, `.version`, `.tool_count`, `.network`, `maef.sandbox.network_open` |

A call with no result, or a sandbox/MCP span never closed, ends at the last event. Never add prompt, argument or result content to a span.

**Export.** `OtlpHttpExporter(endpoint, headers_ref=None)` posts the OTLP/HTTP JSON `resourceSpans` body to `{endpoint}/v1/traces`. Config: `MAEF_OTLP_ENDPOINT`, `MAEF_OTLP_HEADERS_REF`, `MAEF_OTLP_ALLOW_PRIVATE=1`; ledger table `otel_exports(run_id, exported_at)`.

**Metrics (`GET /api/v1/metrics`, Prometheus text 0.0.4, scope `read`).** `maef_runs_total{status,kind}`, `maef_tokens_used_total{kind=input|output}`, `maef_cached_input_tokens_total{kind=read|write}` (a subset of the input tokens above, not additional), `maef_reasoning_tokens_total` (a subset of the output tokens), `maef_cost_usd_total` (provider-reported, information only), `maef_tokens_reserved_open`, `maef_run_duration_seconds_count|_sum` (summary, finished runs, created to finished), `maef_budget_exhaustions_total{reason=tokens|turns|duration}`, `maef_worker_lost_total`, `maef_tool_calls_total{is_error}`, `maef_artifact_bytes_total`.

  - id: greet
    agent_id: research-analyst
    instruction: ...

`maef eval run SUITE [--revision REV ...] [--timeout S] [--json] [--out report.md]` runs the suite per revision (SUITE is a path or a name under `evals/`), prints a markdown comparison (pass rate, total and mean tokens, per-task token deltas against the first revision) and exits 1 when any task failed in the last revision.

## Transcript artifact (`transcript.jsonl`, opt-in)

Written only when the worker runs with `MAEF_RECORD_TRANSCRIPT=1`. Stored as a `text/plain` artifact named `transcript.jsonl` and listed in the manifest. One JSON object per line, in this order:

```
{"type":"system","text":<system instructions>}
{"type":"user","text":<run instruction>}
{"type":"assistant","turn":n,"t":<seconds since run start>,"latency_ms":int,"stop_reason":str,"text":str,"reasoning":str,
 "tool_calls":[{"id":str,"name":str,"arguments":obj}],
 "usage":{"input_tokens","output_tokens","cache_read_tokens","cache_write_tokens","reasoning_tokens","cost_usd"(float|null)},
 "provider":str|null,"response_id":str|null,"model":str|null}
{"type":"tool","turn":n,"t":float,"duration_ms":int,"id":str,"name":str,"arguments":obj,"content":str,"is_error":bool}
{"type":"end","t":float,"status":str,"terminal_reason":str}
```

`assistant` and `tool` lines repeat per turn and per tool call. A failed model call writes no `assistant` line; the `end` line is always written. If the file would be larger than the artifact limit, long strings are shortened (head kept, then `…[truncated N chars]`) until it fits, and `transcript.recorded.truncated` is true.
